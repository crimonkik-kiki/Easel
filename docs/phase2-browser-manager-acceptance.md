# 第二阶段：第 2 项验收记录

范围：仅 Easel。测试账号均为 fake/test；浏览器集成测试仅打开隔离目录中的 about:blank。不访问平台，不读取真实账号资料，不重启生产工作台。

## 实现

- web/browser_manager.py 是同步账号浏览器的唯一启动入口；skills/shared/scripts/browser_manager.py 提供脚本调用桥接。九个账号相关脚本已接入，文档/图片渲染浏览器不使用账号资料目录。
- 原有 SQLite 账号操作锁继续统一登录、打开后台、核验、发布。启动前在 SQLite 保留资料目录占用，调用方崩溃不会删除记录。
- 使用本地进程创建时间识别 PID，通过浏览器 CDP 记录浏览器进程；本地进程树跟踪后续子进程。关闭资料目录必须同时具备 close() 正常返回的保存确认与已记录进程全部退出。
- 打开前检查本机使用同一 user-data-dir 的遗留浏览器。检查失败、启动异常、保存失败和未确认身份均保留占用，不能以脚本返回或进程退出替代资料保存确认。
- 重启只读本地 SQLite 与进程状态，不启动平台访问。人工解除中断前复查执行进程、浏览器进程和资料目录对应的遗留进程。
- 所有账号子进程（含公众号后台登录、创作数据核验）接收同一执行目录、账号 ID 与操作 ID。

## 对照原文第 2 项

| 验收项 | 证据 |
|---|---|
| 同账号登录、打开后台、核验和发布互斥 | 四种 action 的同一 Journal 并发互斥用例；资料目录额外互斥，别名不能同时打开同一目录 |

| 服务重启发现未关闭浏览器，不另起上下文 | 新 Journal/BrowserManager 实例读取相同持久化占用；隔离空白 Edge 遗留窗口被启动前扫描识别，第二次启动被拒绝 |

该记录只验收第 2 项，尚不表示发布队列、冻结提交快照和平台回执已完成。

## 第 3、4 项前置缺口：已停止推进

原文第 4 项要求确认页展示的封面、声明与执行数据一致。现有 PublishRequest 仅 title/body/media/tags，缺少统一封面和声明合同；抖音执行器 _select_ai_cover 在上传后选择平台推荐封面，确认时无法展示和冻结实际封面。先补齐平台适配器的封面/声明能力或明确需要人工交接的平台范围，才能满足原验收标准。没有以“平台默认”代替实际封面验收，也没有落地部分冻结的队列。第 3、4、5 项均未实施。
