## 第 3 项：持久化任务队列和幂等

- `web/publish_queue.py`：SQLite `outputs/_execution/publish.sqlite3` 保存账号、任务 ID、请求幂等键、输入摘要、确认参数摘要、阶段、执行次数和日志。
- prepare 使用 `(account,idempotency_key)` 唯一索引，同键同输入返回原任务，同键不同输入冲突；confirm 核对快照摘要，可安全重放确认。
- 队列全局准入上限 1，事务内 claim；已领取任务不会再次被领取。拥有者中断后进入待核对，不自动恢复执行。当前所有任务只准备本地人工交接，不调用发布浏览器。
- 刷新页面仍可查看任务与阶段日志；未确认任务可以重新打开原确认页，不必重建参数。
- 旧 HTTP 直接发布返回 428；相关旧项目 CLI 发布入口禁止绕过队列，登录和本地计划功能保留。

原验收逐条自查：刷新保留阶段/目标账号/日志 **通过**；同一任务不重复执行 **通过**；任务 ID/幂等键可查 **通过**。API 回归、并发 claim、服务对象重建及隔离 UI 刷新均有用例。

## 第 4 项：每账号分级冻结

- `web/publish_snapshot.py` 在确认前解析实际标题、完整正文、账号话题和尾注，B站现有截断、标签规范化及自制值均明确显示。
- 媒体流式复制到私有内容寻址目录，保存 SHA-256 和大小。确认与队列交接检查副本完整性；原文件/账号预设随后改变不影响副本或参数。
- 公众号首图作为实际已冻结封面展示；未知封面明确显示待人工确认。未知 AI/原创声明明确标出，不能以省略声明宣称闭环。
- `PublishConfirmDialog.tsx` 展示服务端保存的实际参数；确认请求只发送任务 ID 与参数摘要，不从前端表单或最新预设重新构造数据。
- 人工交接提供冻结文案复制与冻结媒体下载。人工完成最终封面/声明选择后，只能明确记录人工核对的结果，不能谎称这些未知字段已经自动冻结。

原验收按本次分级决策自查：可确定封面与实际文案一致 **通过**；不可确定封面进入专用人工状态 **通过**；未知声明明确披露 **通过**；修改预设不影响已确认任务 **通过**。七个平台快照、媒体篡改、原文件删除和确认后预设修改均有隔离测试。

## 第 5 项：平台回执与重试策略

- `web/publish_receipts.py` 统一记录：草稿、已提交、审核中、已发布、拒稿、提交结果未知、待核对、待人工验证、提交前失败。提交阶段与结果状态分别保存。
- 当前能力矩阵下来源均为 `manual_confirmation`，界面明确显示人工核对，不把退出码 0、页面跳转或自动推荐封面当作发布证据。
- 保存回执、推进任务状态、追加日志和写入结果发件箱在同一 SQLite 事务完成。回传失败时同回执幂等键读取已存结果；不会重新 claim 或发布。
- 回执绑定任务、账号与确认参数摘要，带版本检查；不能跨账号回写或覆盖较新的结果。结果发件箱确认同样校验范围。
- 所有原任务重试均被禁止。未知结果、已提交、审核中或拒稿任务的相同内容，即使换幂等键也不能再次确认；拒稿须修改内容另建任务。修改后新任务仍是人工交接，不自动发文。
- 已知提交阶段不会被后来未知结果抹除，也不能降为“提交前失败”或草稿以放开重发。公开链接去掉查询令牌，不保存 Cookie、密钥字段。

原验收逐条自查：提交后断网、页面跳转、验证码、审核中、拒稿和未确认均有明确状态 **通过（模拟人工核对回执）**；提交后的未知状态不能自动原样重试 **通过**。没有宣称已验证真实平台或已获得自动发布授权。

## 使用方式

发布中心选择账号与素材 → 准备发布任务 → 逐账号查看冻结参数 → 确认加入人工交接队列 → 任务详情中复制文案/下载媒体 → 人工在平台确认封面和声明并完成操作 → 返回任务详情记录实际平台回执。结果未知先核对，不重新提交原任务。
