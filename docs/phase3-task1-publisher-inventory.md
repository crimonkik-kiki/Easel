## 发现的实际阻塞（不是平台公开契约问题）

1. **缺少提交前硬停点。** 两个脚本没有 `prepare-only` / `stop-before-submit` 参数。去掉旧发布门禁后，抖音 `_fill_title_desc` 下一步直接调用 `_click_publish`；视频号专用函数直接聚焦发表按钮并按 Enter。不能用这些入口声称“仅走到最后一步”。
2. **最小可见性尚未实现。** 两个发布器没有实际的 visibility/仅自己可见控制，也没有完整声明应用及读回。运行旧 `--exec` 入口无法保证老板要求的最小暴露范围。
3. **有重复提交路径。** 抖音首次提交后，若仍停留发布 URL，收尾阶段存在再次 `_click_publish` 的路径；视频号函数在未跳转时换 frame 重试发表。函数注释中的“单次提交契约”不等于全调用链已经满足该约束。
4. **启动参数仍有硬约束冲突。** 两个脚本备用 LAUNCH_ARGS 中保留 AutomationControlled；通用脚本还有 disable-gpu，启动调用显式覆盖 locale。当前原生 Edge 分支可以避开一部分备用参数，但不能据此将所有 Chromium 路径判为安全。不能直接拿这些旧启动路径跑本轮真实账号测试。
5. **第二阶段门禁明确阻止真实脚本发布。** 它需要按第三阶段要求有条件接线，不能为了实测直接移除并让旧入口公开提交。

按照“遇阻立即停止”的要求，本轮停在清点/离线/内核验证，没有访问真实账号、上传素材、触发声明/验证码或点击真实提交。任务 1 **尚未验收完成**，任务 3 和任务 2 **未开始**。

继续前需先建立不带伪装参数的审计启动路径、提交前硬停点、真实可见性读回和单次提交保护；随后才可按授权执行持久化账号只读核验及提交前端到端实测。任何实际提交仍须先给出完整参数清单，取得确认，并使用平台允许的最小可见范围。
