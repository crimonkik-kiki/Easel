# Clipify 中文直播切片适配方案

状态：首版阶段1–3已实施并部署（2026-10-26）；结果、限制和实测证据见 `clipify-adaptation-acceptance-2026-10-26.md`。以下保留方案及后续扩展边界。依据：2026-10-26 两份本地录屏实测，以及当前 Clipify、asr.py、highlight_cut.py、reframe.py 源码。

## 1. 目标与默认体验

用户在工作台给出本地视频路径或选择本地视频，说“从这段直播切出3条知识短视频”，即可完成：

检查素材 → 本地转录 → 全片内容选段 → 生成带字幕短片 → 在内容库预览和下载。

首版默认：中文知识/课程场景，3条，目标每条20–60秒，原帧率，简洁白色中文字幕，本地转录。生成前提供画幅选择：横屏16:9、竖屏9:16、保持原比例。首次默认保持原比例，记住用户上次选择；用户明确指定的画幅优先。优先保证语义完整，不能为了凑时长切断一句话；确实无法在范围内表达完整的候选标明原因，不静默超长。

画幅选项放在生成设置中，生成按钮旁即可查看与修改，不增加反复确认弹窗。通过对话发起时识别用户已指定的画幅；未指定则沿用已显示的设置。用户可以查看候选、换片段、修改字幕再重出。

范围限定在 Easel。沿用现有对话/技能执行与内容库，不改账号管理、发布链路、运营分析，不依赖 WorkBuddy 尚未完成的接入。

## 2. 实测问题与处理决定

| 当前证据 | 适配决定 | 验证方式 |
| --- | --- | --- |
| 原说明使用 python3、Bash、/tmp，当前机器可能命中其他项目解释器 | 统一项目 Python、参数数组和 pathlib；产物及缓存写入项目 outputs | 中文/空格路径、不同启动目录测试 |
| 当前 PyAV 文件读取入口不接受 metadata_errors | FFmpeg 解码成16kHz单声道PCM，用稳定输入接口交给 faster-whisper；预检实际依赖组合，不直接降级全项目依赖 | 在当前 av 19.0.1 + faster-whisper 1.2.1 环境跑真实语音样例 |
| 项目 asr.py 的JSON只有段级时间与文字 | 增加可选逐词输出，保留原字段和默认输出行为，避免影响其他技能 | 旧调用回归、逐词结构/偏移检查 |
| runtime/bin 当前仅查到 ffmpeg.exe，复用脚本需要 ffprobe | 先定位已装工具和工作台配置；缺少 ffprobe 则明确报缺项并补齐项目级运行工具，禁止假装满足依赖 | 预检给出真实工具路径、版本、可用滤镜 |
| 第一份录屏低音量长静音95.55%，没有有效转录 | 区分无音轨、长静音、未检测到人声、识别失败；不生成虚构文案或空字幕成片 | 无声、纯音乐、带人声样例分别测试 |
| 毛毛录屏可转录1421段，完整样片链路通过 | 把隔离测试中的可靠流程整理成正式脚本，不继续依赖 outputs 内临时脚本 | 从正式入口重复生成样片 |
| base 模型对 WorkBuddy、Skill、Token 等容易误识别 | 使用课程术语词表；原始文本与修订文本分开；低置信度标记，修订可追溯 | 同音字/术语样例，检查没有改写原意 |
| 原字幕固定1080×1920、英文6词分组 | 尺寸和字体自适应，按中文长度、标点、停顿分组；同一字幕布局器支持横竖屏 | 2560×1440、1920×1080、1080×1920抽帧检查 |
| analyze.py 把时间写死为30fps，而两份素材都是20fps | 使用ROI日志真实 pts_time 对齐，检查单调性和双路覆盖；禁止用帧索引/30推算 | 20/25/30/60fps和非恒定时间间隔测试 |
| 原裁切流程更适合固定双人机位 | 屏幕演示默认保留全画面；双人切换作为单独模式，检测条件不满足则明确提示 | 屏幕录制不触发人脸裁切；多人/镜头切换有明确状态 |

## 3. 功能分层与拟修改位置

以下文件名为拟定实施位置，不代表已经新增。

### 3.1 稳定的技能入口

- 新增 `skills/shared/scripts/clipify.py`，提供 `check / transcribe / render / status / resume / cancel` 子命令。
- 更新 `skills/builtin/clipify/SKILL.md`：中文课程、访谈、娱乐三个选段场景；统一Windows示例，明确能力边界和默认值。
- 技能负责调用现有 Agent 阅读转录、输出候选；脚本负责媒体处理与严格验证。模型未配置时明确提示内容选段不可用，可接受用户提供的时间段，不拿音量峰值冒充教学内容判断。
- `video-highlights` 与 Clipify 共用转录和切片底层，不维护两套相同实现。前者保留快速能量选段，Clipify承担内容选段与精细字幕流程。

### 3.2 媒体与转录

- 扩展 `skills/shared/scripts/asr.py`：可选逐词时间戳、术语提示、明确模型来源，保留现有调用兼容性。
- 复用 `highlight_cut.py` 的切片清单与精确裁切逻辑；必要公共能力提取为共享函数，不复制临时 FFmpeg 命令到多处。
- 长音频按可配置时间窗处理，记录源视频绝对偏移，边界采用短重叠并去重，避免将整小时音频反复载入和重复转录。
- 缓存按源文件指纹、音轨、模型、语言、参数和版本区分。源文件发生改变必须使缓存失效；完整源文件哈希用于验收，不把仅路径相同当成相同素材。
- 优先现有本地模型。更大模型是质量选项，不自动声称base达到专业听校精度；模型不可用则清楚报告，不后台更换云服务。

### 3.3 全片内容选段

- 按主题/转录时间分块提出候选，再全局排序、去重。避免只看开头几分钟便宣称找到全片精华。
- 知识课程侧重完整观点、可操作步骤、案例结论；娱乐访谈才侧重笑点和反转。
- 每个候选必须包含标题、源片起止时间、所依据的转录段ID、选取理由、适合用途、质量提示。
- 后端验证时间范围、字幕段来源、候选之间重叠和重复内容；拒绝模型编造的时间点及不存在的原话。
- 边界对齐真实词/句时间，保留可配置的前后留白；不为满足精确秒数截断句尾。
- 原声保留。不把说话人的立场、批评或限定条件从上下文中切掉。

### 3.4 中文字幕与画幅

- 改造 `skills/builtin/clipify/scripts/build_ass.py`：参数化目标分辨率、字体、字号、边距、样式；UTF-8显式读写。
- 中文按标点、停顿、显示长度和阅读时间分组，英文保留词间空格；默认最多两行。
- 默认底部安全区域，支持用户调整以避开原字幕/软件工具栏。首版不承诺自动理解所有画面并找到最佳位置。
- 输出原始转录、修订记录、SRT和ASS；逐字高亮仅在真实词级时间戳可用时开放，不能用段级时间平均切分冒充逐字对齐。
- 术语校正记录来源。无法确认的语义性改动只提供建议，不偷偷改写；内容未听校的状态如实保留。
- 首版即提供画幅选择器：`source`（保持原比例）、`16:9`（横屏）、`9:16`（竖屏）。该字段贯穿生成设置、技能参数、任务清单和重新生成流程；创建任务时保存本次选择，后续更改偏好不改变正在执行的任务。
- 保持原比例时沿用源视频尺寸；选择横/竖屏时按目标比例输出，字幕根据最终画布重新排版。竖屏常用输出为1080×1920，最终尺寸在任务清单中明确记录。
- 横竖屏转换默认等比缩放、完整画面居中、模糊背景填充，避免裁掉课件或软件界面；人物裁切是另行显式选择的策略，由 `reframe.py` 等已有能力承担，并如实声明局限。
- 内容库每条成片标注“横屏/竖屏/原比例”及实际分辨率，允许同一个片段分别导出横屏和竖屏。画幅变化使渲染缓存失效，但可以复用有效转录和选段结果。
- 加固 `analyze.py`、`build_pan.py`：空输入、不匹配时间线、越界坐标和多镜头异常应有可读错误；音频对齐工具保留为可选能力。

### 3.5 任务状态与内容库

- 对话触发正式入口，进度显示“检查/提取音轨/转录/选段/渲染/核验”。耗时操作在受控子进程执行，支持取消和恢复；不阻塞Web请求线程。
- 每个任务独立目录和进程标识。取消只结束本任务子进程，不用进程名批量杀掉整台机器的 Python/FFmpeg。
- 单机默认一个重转录任务，渲染并发受限；不创建新的发布队列或通用调度系统。
- `outputs/clipify/<task-id>/manifest.json` 记录输入、参数、阶段、模型、候选、输出与验证结果；中间文件有清理策略。
- 内容库展示工作台生成的成片、字幕和片段清单。原始本地视频只被读取，不复制为内容库素材；尽量利用现有媒体预览能力。
- 完成采用临时输出→核验→最终文件的顺序。失败或取消时，不把半成品标记为成功。
- 技术核验与内容校对分开显示：文件可播放不等于字幕准确，自动字幕不等于已审核稿。

## 4. 实施顺序与交付

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 1：正式脚本闭环 | Windows预检、稳定PCM转录、逐词JSON、中文ASS/SRT、画幅参数及基础填充、精确切片、清单 | 脱离临时脚本，正式入口重现毛毛录屏3条样片并验证三种画幅参数；原有字幕/切片调用不退化 |
| 2：可靠选段与长任务 | 全片分块候选、来源验证、排序去重、缓存、恢复、取消 | 中断可恢复；缓存不串片；无需反复确认基础格式；无声样例明确停止 |
| 3：接入工作台 | 技能入口、横屏/竖屏/原比例选择、阶段进度、内容库预览、重出字幕/片段 | 用户在工作台能完成“给路径→选画幅→看成片”，已有账号/发布模块不受影响 |
| 4：扩展模式 | 人物动态裁切、双人跟随、可选逐字高亮 | 各模式有独立验收，未达标模式不标为可用 |

首个可用版本以阶段1–3为范围，包含基础横竖屏选择与完整画面填充。阶段4扩展人物动态裁切、双人跟随等高级模式，不阻塞中文课程切片交付。

## 5. 验收标准

### 自动检查

1. 当前环境可通过正式预检；路径指向项目运行时，缺依赖或模型则明确失败。
2. 源文件只读，输出全部在任务目录；中文和空格路径可用。
3. 逐词时间有效、有来源；分块后绝对时间正确、边界没有重复字幕。
4. 导出时长与清单误差不超过0.10秒；画幅符合用户本次选择，保持原比例模式保留源尺寸，横屏/竖屏分别满足16:9/9:16，默认保留帧率；非恒定帧率另验时间戳，不强制伪装为固定帧率。三种模式分别检查字幕不越界、画面默认未被裁切；设置改变不串用旧画幅的渲染缓存。
5. 每个成片完整解码退出码0；音视频流存在，字幕不越界、不重叠。
6. 取消后任务子进程退出，不产生成功成片；恢复不重跑已核验阶段，不复用不同素材缓存。
7. 新功能有真实场景用例；共享ASR、video-highlights、字幕输出和内容库相关既有测试通过，不以合成测试替代真实录屏验收。

### 用两份真实素材回归

- `20261019_100259.mp4`：应报告“未检测到有效人声/无法可靠选段”，保留诊断结果，不能输出编造字幕或把空字幕文件当成功。
- `20260806_毛毛录屏.mp4`：完成全片转录和候选来源验证，至少复现这次3条教学短片；检查片头片尾是否完整、关键术语、字幕显示和声画对应。
- 20/25/30/60fps及可变时间间隔用小型专用素材测试，不将真实20fps视频当成30fps处理。

### 内容质量抽检

选段完整性、关键人名/产品名/数字、字幕与原声对应需要实际抽听；无法只凭解码和时间轴测试盖章。自动识别稿可以交付预览，但必须保留未听校状态。若要求正式发布级准确度，应另约定听校范围与标准，不以“技术测试通过”代替。
